## 第一批改动

`createPinResolver` 为一次绘制建立元件快照，按需计算并复用真实引脚坐标，避免每根导线的两个端点都线性扫描元件数组。每次重新绘制都重新创建；不能跨移动、旋转、撤销或导入复用旧快照。返回坐标副本，端点预览不能污染其他导线。

`paintCrossingWires` 复用已生成的路由顶点，减少重复生成正交路径。超过原有 720 线段的装饰预算时，在分配线段对象和索引之前退回普通导线；导线本身仍完整显示、可编辑。

小场景继续直接扫描。较大且稀疏的场景使用包围盒树过滤无关线段；密集场景通过固定采样回退直接扫描，避免索引本身成为负担。当前采样为 24 个线段，至少 256 个线段、采样包围盒重叠比例低于 25% 时使用索引。这是计算策略，不影响显示或连接语义。

每根导线按真实路由顺序处理交叉点，满足原有最多 24 个跳线拱后停止发现后续交叉点。不改变拱的选择顺序，不减少原有上限，不增加隐式电气节点。

## 回归与基准

`tests/wire-performance.test.mjs` 包含 25 项确定性检查：全部引脚及多种旋转、快照隔离、元件查找次数、空场景、17 组旧版绘制输出摘要、缺失端点、临时改接预览、旧版/正交路由和 32 折点上限。

旧版参考为提交 `813d676dbfa9639b77a582b9e6f884f122773392`。`tests/fixtures/wire-paint-alpha10.json` 保存原算法输出的 SHA-256，不应在新实现失败时直接按新结果重写。确认是有意的视觉行为变更后，才能同时更新相应测试和变更说明。

`e2e/wire-performance.spec.ts` 在 300 元件、2000 导线的导入上限场景中检查：正常显示、缩放不改世界坐标路径、键盘微移后导线跟随、单步撤销恢复完整工程、无页面运行错误。它是交互正确性测试，不是 FPS 测试。

运行几何基准：

```sh
npm run bench:wires
```

与已编译的旧版本比较：

```sh
npm run bench:wires -- --baseline /path/to/alpha10/.test-dist/core/wire-crossings.js
```

基准使用固定种子，覆盖小场景、600 线段稀疏布局、720 线段密集交叉、2000 根普通导线及 2000 根各含 32 折点的导线。先预热，再交替执行比较对象，报告 40 个样本的 p50/p95。报告包括 Node、CPU 和平台信息。

**这些数字只表示导线几何函数耗时，不含 DOM、浏览器绘制、事件处理和电气求解，不能换算或宣传为编辑器 FPS。** 不把共享 CI 机器的绝对耗时设为不稳定的单测门禁。

## 后续接入约束

触控和触控笔仍应使用统一的 Pointer Events 状态管理。手势的 pointerId、捕获、取消、兼容 click 和第二根手指介入需要一起处理，不能只扩大命中区就称为触控支持。

选择、吸附参考线和指针状态必须保持瞬态。导线端点 ID、颜色、既有世界坐标折点和单步撤销仍受根目录 AGENTS.md 约束。任何接线行为改变都要补 Chromium、Firefox、WebKit 回归；原生 Safari、真实笔设备和原版登录编辑器的逐项对照仍单列验收。

目标继续是向 Tinkercad Circuits 对齐；本批没有新的 1:1 或设备支持完成声明。
